# Drone Control: документация проекта

WPF-пульт на .NET 10 для управления TX-дронами (приложение **KY FPV**, пакет `com.cooingdv.kyfpv`) с ПК по Wi-Fi.
Протокол управления восстановлен из декомпилированного APK.

> **Статус (18.10.2026).**
> - Решение собирается на .NET SDK 10.0.402 без ошибок и предупреждений.
> - Все 17 тестов (11 методов, один из них с 7 наборами данных) проходят.
> - Интерфейс при составлении документа не запускался.
> - На живом дроне ничего не проверялось: протокол восстановлен по декомпилированному коду.
>   Первые запуски делайте **без пропеллеров**.

## 1. Назначение и возможности

Программа заменяет экранный пульт Android-приложения: ПК подключается к Wi-Fi точке дрона и шлёт ему
те же UDP-пакеты, что и телефон.

Что умеет:

| Функция | Как реализовано |
|---|---|
| Подача газа | Вертикальный слайдер 0…255 (0–100 %), кнопки «0» и «128» |
| Взлёт / посадка | Кнопки-пресеты, флаги `0x01` / `0x02` на 1 с |
| Зависание | Крен, тангаж и рыскание = 128 |
| Движение | Вперёд, назад, влево, вправо (крен и тангаж) с настраиваемой мощностью и длительностью |
| Углы | Поворот влево и вправо (рыскание), флип |
| Сценарий | «Демо»: взлёт → вперёд → поворот → назад → посадка |
| Калибровка | Гироскоп, флаг `0x80` на 2 с |
| STOP | Прерывает текущую команду, снимает флаги и переводит дрон в зависание (кнопка или **Esc**) |
| Стоп моторов | Аварийное отключение моторов, флаг `0x04` |
| Диагностика | Индикаторы каналов, hex последнего пакета, журнал отправленных и принятых данных |
| Dry-run | Пакеты формируются и показываются, но в сеть не уходят |

## 3. Сборка, тесты, запуск

Все команды выполняются из корня `DroneControl`.

Проверить, что SDK установлен:

```bash
dotnet --list-sdks
```

Прогнать тесты:

```bash
dotnet test
```

Запустить пульт:

```bash
dotnet run --project src/DroneControl.Wpf
```

Собрать готовую папку с exe (нужен установленный .NET 10 Desktop Runtime на целевой машине):

```bash
dotnet publish src/DroneControl.Wpf -c Release -o publish
```

Решение открывается в Visual Studio 2022 17.13+ или VS 2026 через `DroneControl.slnx`.

### 4.2. Порядок работы

1. **Подключитесь к Wi-Fi дрона** с ПК. Телефон с оригинальным приложением от дрона отключите
   (см. [приложение Б](#приложение-б-видеопоток-и-ограничение-на-одного-клиента)).
2. Проверьте поля «IP дрона» (`192.168.1.1`) и «UDP порт» (`7099`).
3. Нажмите **«Подключить»**. Начнёт уходить heartbeat `01 01` раз в секунду, в шапке появится «только heartbeat».
4. Включите переключатель **«Передача управления»**. Пакеты управления пойдут каждые 50 мс.
   Кнопки команд станут активными только после этого.
5. Управляйте газом и кнопками.
6. Чтобы закончить, выключите «Передачу управления» (дрону уйдёт `08 01`) и нажмите «Отключить».

### 4.3. Газ

- Слайдер задаёт байт газа 0…255. Сверху отображаются проценты и сам байт.
- **«0»**: газ на минимум.
- **«128»**: центр. У дронов с барометром это обычно «держать высоту».
- **«Удержание высоты»**: если включено, газ автоматически ставится в 128:
  - при включении самого режима;
  - при включении передачи управления;
  - при «Взлёт», «Зависание» и STOP.

Значение газа сохраняется и применяется сразу после подключения. Пресеты газ **не меняют**
(кроме перечисленных выше случаев и аварийного стопа), им управляете только вы.

### 4.4. Кнопки-пресеты

| Кнопка | Что делает | Длительность |
|---|---|---|
| **Взлёт** | Стики в центр, флаг `0x01` | 1 с |
| **Посадка** | Стики в центр, флаг `0x02` | 1 с |
| **Зависание** | Крен, тангаж и рыскание = 128 | мгновенно |
| **Демо-сценарий** | Взлёт, пауза 3 с, вперёд 1 с, пауза 1 с, поворот вправо 1 с, пауза 1 с, назад 1 с, пауза 1 с, посадка | ≈ 11 с |
| **Вперёд / Назад** | Тангаж ±«Мощность» | «Длительность» |
| **Влево / Вправо** | Крен ±«Мощность» | «Длительность» |
| **Поворот влево / вправо** | Рыскание ±«Мощность» | «Длительность» |
| **Флип** | Тангаж 100 % вперёд + флаг `0x08` | 600 мс |
| **Калибровка** | Флаг `0x80` (только на земле!) | 2 с |

Параметры внизу карточки:

- **Мощность движения**: 10–100 % с шагом 5 %.
- **Длительность движения**: 0,2–5 с с шагом 0,1 с.

Мощность и длительность считываются в момент нажатия кнопки.

Правила выполнения:

- Одновременно выполняется **только один** пресет. Нажатие новой кнопки прерывает текущий.
- Пока пресет идёт, справа вверху карточки крутится индикатор и видно его название.
- Движение при любом завершении, будь то таймаут, отмена или ошибка, возвращает стики в центр.

### 4.5. STOP и стоп моторов

| | STOP (красная кнопка, **Esc**) | Стоп моторов (контурная кнопка) |
|---|---|---|
| Пресет | прерывается | прерывается |
| Временные флаги (взлёт, посадка и др.) | снимаются | снимаются |
| Стики | в центр | в центр |
| Газ | не меняется (128 при «Удержании высоты») | **0** |
| Флаг `0x04` | — | на 1 с |
| Последствия | дрон зависает | **моторы встают, дрон падает** |

### 4.6. Правая панель

- **Отправляемые каналы**: значения последнего отправленного пакета (обновляются 10 раз в секунду).
- **Флаги**: hex и расшифровка, например `0x01 · TakeOff`.
- **Последний пакет**: все 9 байт в hex.
- **Экспериментальные флаги**: постоянные биты `0x10`, `0x20`, `0x40` (см. [§13](#13-известные-ограничения-и-непроверенные-места)).
- **Журнал**, новые записи сверху, хранится максимум 300 строк:

| Префикс | Значение |
|---|---|
| `→` | отправленный пакет управления (только когда он **изменился**, иначе было бы 20 строк в секунду) |
| `←` | данные, пришедшие от дрона |
| `▶` / `✓` / `■` / `✗` | старт, успешное завершение, прерывание и ошибка пресета |

  Повторяющиеся ошибки отправки пишутся один раз.

### 4.7. Режим Dry-run

Отметьте «Dry-run» **до** подключения. Всё работает как обычно, но транспорт `DryRunTransport`
ничего не отправляет в сеть. Так можно проверить интерфейс и формат пакетов без дрона.

## 5. Протокол управления

### 5.1. Транспорт

- **UDP**, дрон `192.168.1.1`, порт **7099**.
- Локальный порт любой (эфемерный), как и в оригинале: `new DatagramSocket()` без `bind`.
- Дрон отвечает на тот же сокет. Ответы принимаются и выводятся в журнал.

### 5.2. Пакеты

| Пакет | Байты | Когда |
|---|---|---|
| Heartbeat | `01 01` | раз в 1 с, всё время подключения |
| Управление | `03 66 RR PP TT YY FF CS 99` | каждые 50 мс, пока включена передача управления |
| Выход из управления | `08 01` | однократно при выключении управления |

Остальные служебные команды оригинала в проект **не перенесены**: `09 01` и `09 02` (подтверждения фото и видео), команды камеры.

### 5.3. Пакет управления подробно

| Смещение | Поле | Диапазон | Описание |
|---|---|---|---|
| 0 | префикс | `0x03` | Тип «данные пульта» (добавляет `DeviceTXFragment.sendFlyControllerData`) |
| 1 | заголовок | `0x66` | Константа `CONTROL_VALUES_BYTE0 = 102` |
| 2 | RR | 1…255 | Крен (`controlByte1`). 128 = центр, > 128 = вправо* |
| 3 | PP | 1…255 | Тангаж (`controlByte2`). 128 = центр, > 128 = вперёд* |
| 4 | TT | 0…255 | Газ (`controlAccelerator`). Значение 1 заменяется на 0 |
| 5 | YY | 1…255 | Рыскание (`controlTurn`). 128 = центр, > 128 = вправо* |
| 6 | FF | битовая маска | Флаги, см. 5.4 |
| 7 | CS | — | `RR ^ PP ^ TT ^ YY ^ FF` |
| 8 | конец | `0x99` | Константа `CONTROL_VALUES_BYTE7 = 153` |

\* Направления и порядок «крен/тангаж» взяты из декомпиляции и типичных протоколов таких дронов,
на живом дроне не проверены.

Примеры:

| Состояние | RR | PP | TT | YY | FF | CS | Пакет |
|---|---|---|---|---|---|---|---|
| Стики в центре, газ 0 | 80 | 80 | 00 | 80 | 00 | 80 | `03 66 80 80 00 80 00 80 99` (проверяется тестом) |
| Зависание, газ 128 | 80 | 80 | 80 | 80 | 00 | 00 | `03 66 80 80 80 80 00 00 99` |
| Взлёт, газ 128 | 80 | 80 | 80 | 80 | 01 | 01 | `03 66 80 80 80 80 01 01 99` |
| Вперёд 50 %, газ 128 | 80 | C0 | 80 | 80 | 00 | C0 | `03 66 80 C0 80 80 00 C0 99` |

Расчёт CS для зависания: `80 ^ 80 = 00`, `00 ^ 80 = 80`, `80 ^ 80 = 00`, `00 ^ 00 = 00`.

### 5.4. Флаги (байт FF)

| Бит | Маска | Имя в коде | Назначение | Длительность в оригинале | Достоверность |
|---|---|---|---|---|---|
| 0 | `0x01` | `TakeOff` | Взлёт одной кнопкой | 1 с | высокая |
| 1 | `0x02` | `Land` | Посадка одной кнопкой | 1 с | высокая |
| 2 | `0x04` | `EmergencyStop` | Аварийная остановка моторов | 1 с | высокая |
| 3 | `0x08` | `Flip` | Флип в сторону отклонения стика | 600 мс | высокая |
| 4 | `0x10` | `Headless` | Предположительно headless | постоянно | **низкая** |
| 5 | `0x20` | `ReturnOrUnlock` | Возврат или разблокировка моторов | — | **низкая** |
| 6 | `0x40` | `Light` | Предположительно подсветка | постоянно | **низкая** |
| 7 | `0x80` | `GyroCalibration` | Калибровка гироскопа | 2 с | высокая |

«Высокая» достоверность: бит однозначно связан с методом `FlyController`, у которого есть таймер сброса
(`setFastFly`, `setFastDrop`, `setEmergencyStop`, `setCircleTurnEnd`, `setGyroCorrection`).
Для битов 4–6 декомпилятор оставил только синтетические методы `access$500`, `access$600`, `access$800`
без однозначной привязки к полям.

### 5.5. Временные диаграммы

Взлёт:

```
t, мс:   0    50   100  …  950  1000 1050
FF:     01   01   01   …   01   00   00
```

Флип вперёд:

```
t, мс:   0  …  550   600  650
PP:     FF  …   FF    80   80
FF:     08  …   08    00   00
```

## 6. Архитектура

```
┌──────────────────────── DroneControl.Wpf ────────────────────────┐
│ MainWindow.xaml ──binding──► MainViewModel                        │
│                               │  команды, свойства, журнал        │
│                               │  DispatcherTimer 100 мс → индикаторы
└───────────────────────────────┼───────────────────────────────────┘
                                ▼
┌──────────────────────── DroneControl.Core ───────────────────────┐
│ FlightPresets ──► DroneClient ──► IDroneTransport                 │
│  (сценарии)        │ состояние стиков/флагов (Lock)               │
│                    │ heartbeat-цикл   1 с   ┐                     │
│                    │ control-цикл    50 мс  ├─ PeriodicTimer      │
│                    ▼                        ┘                     │
│               DroneProtocol (чистые функции сборки пакетов)       │
│                                                                   │
│   IDroneTransport ─┬─ UdpDroneTransport  (UdpClient + приём)      │
│                    └─ DryRunTransport    (no-op)                  │
└───────────────────────────────────────────────────────────────────┘
```

### Принципы

- **Core не знает про UI.** Его можно использовать из консоли, тестов или другого UI.
- **Состояние отделено от отправки.** UI и пресеты только меняют значения в `DroneClient`,
  а фоновый цикл раз в 50 мс берёт снимок (`Snapshot`) и отправляет его. Так устроен и оригинальный
  `FlyController`: таймер шлёт текущие поля, кнопки лишь меняют поля.
- **Временные флаги без таймеров.** Для каждого бита хранится момент истечения (`_pulseExpiry`).
  Флаг активен, пока «сейчас» < «истечение». Сбрасывать нечего и гонок нет. Время берётся из `TimeProvider`,
  поэтому в тестах его можно подменить.
- **Пресеты — обычные `async`-методы с `CancellationToken`.** Отмена и есть STOP.
  Движение оборачивается в `try/finally { Hover(); }`.

### Потоки

| Поток | Что делает |
|---|---|
| UI (Dispatcher) | Ввод, `MainViewModel`, `DispatcherTimer` индикаторов, запуск пресетов |
| ThreadPool: heartbeat | `RunLoopAsync(1 с)` |
| ThreadPool: control | `RunLoopAsync(50 мс)`, вызывает `ControlPacketSent` |
| ThreadPool: приём | `UdpDroneTransport.ReceiveLoopAsync`, вызывает `DataReceived` |

События Core приходят из фоновых потоков. `MainViewModel` перекладывает их в UI через
`Dispatcher.InvokeAsync`, а последний пакет хранит в `volatile`-поле, которое читает таймер UI.

## 7. Справочник API (DroneControl.Core)

### 7.1. `DroneProtocol` (static)

| Член | Описание |
|---|---|
| `DefaultHost = "192.168.1.1"` | Адрес дрона по умолчанию |
| `DefaultPort = 7099` | UDP-порт управления |
| `HeartbeatInterval` = 1 с | Период heartbeat |
| `ControlInterval` = 50 мс | Период пакетов управления |
| `FlagPulseDuration` = 1 с | Удержание флагов взлёта, посадки и стопа |
| `FlipPulseDuration` = 600 мс | Удержание флага флипа |
| `GyroCalibrationDuration` = 2 с | Удержание флага калибровки |
| `ControlPacketLength = 9` | Длина пакета управления |
| `byte[] Heartbeat()` | `01 01` |
| `byte[] ExitControl()` | `08 01` |
| `byte[] BuildControlPacket(ControlState)` | Собирает 9-байтный пакет. Оси ограничиваются снизу единицей, газ 1 превращается в 0 |
| `byte Checksum(r, p, t, y, f)` | XOR пяти байт |
| `byte AxisFromPercent(double)` | −100…+100 % → 1…255 (0 % → 128), округление от нуля, выход за диапазон обрезается |

### 7.2. `ControlState` (readonly record struct)

`ControlState(byte Roll, byte Pitch, byte Throttle, byte Yaw, DroneFlags Flags)`:

- `Center = 128`;
- `Neutral`: стики в центре, газ 0, флагов нет.

См. [§5.4](#54-флаги-байт-ff).

### 7.4. `DroneClient` (IAsyncDisposable)

```csharp
var client = new DroneClient(new UdpDroneTransport("192.168.1.1", 7099));
client.Start();                 // heartbeat
client.SetThrottle(128);
client.EnableControl();         // пакеты каждые 50 мс
await FlightPresets.TakeOffAsync(client, ct);
await FlightPresets.MoveAsync(client, 0, 50, 0, TimeSpan.FromSeconds(1), ct);
await FlightPresets.LandAsync(client, ct);
await client.DisposeAsync();    // 08 01 + закрытие сокета
```

| Член | Описание |
|---|---|
| `DroneClient(IDroneTransport, TimeProvider? = null)` | Конструктор. Без `TimeProvider` используется системное время |
| `void Start()` | Запускает heartbeat. Повторный вызов ничего не делает |
| `void EnableControl()` | Запускает цикл пакетов управления. Повторный вызов ничего не делает |
| `Task DisableControlAsync()` | Останавливает цикл и шлёт `08 01` |
| `bool IsControlEnabled` | Идёт ли цикл управления |
| `string TransportDescription` | Например `UDP 192.168.1.1:7099` |
| `void SetSticks(roll, pitch, yaw)` | Значения осей в байтах |
| `void SetThrottle(byte)` | Газ |
| `void Hover()` | Крен, тангаж и рыскание = 128, газ не меняется |
| `void SetFlag(DroneFlags, bool)` | Постоянный флаг (режимы) |
| `void PulseFlag(DroneFlags, TimeSpan)` | Временный флаг, снимается сам |
| `void ClearPulses()` | Снять все временные флаги |
| `ControlState Snapshot()` | Текущее состояние: постоянные флаги плюс ещё не истёкшие временные |
| `event Action<byte[]> ControlPacketSent` | Каждый отправленный пакет управления (фоновый поток) |
| `event Action<byte[]> DataReceived` | Данные от дрона (фоновый поток) |
| `event Action<Exception> SendFailed` | Ошибка отправки (фоновый поток). Цикл при этом **продолжается** |
| `ValueTask DisposeAsync()` | Выключает управление, останавливает heartbeat, закрывает транспорт |

Все сеттеры и `Snapshot()` потокобезопасны (`System.Threading.Lock`).
`EnableControl` и `DisableControlAsync` рассчитаны на вызов из одного потока (UI).

### 7.5. `FlightPresets` (static)

| Метод | Поведение |
|---|---|
| `TakeOffAsync(client, ct)` | `Hover()` + `TakeOff` на 1 с, ожидание 1 с |
| `LandAsync(client, ct)` | `Hover()` + `Land` на 1 с, ожидание 1 с |
| `HoverAsync(client, ct)` | `Hover()` |
| `MoveAsync(client, roll%, pitch%, yaw%, duration, ct)` | Отклоняет стики на `duration`, в `finally` вызывает `Hover()` |
| `FlipAsync(client, FlipDirection, ct)` | Стик на 100 % в нужную сторону + `Flip` на 600 мс, в `finally` вызывает `Hover()` |
| `CalibrateGyroAsync(client, ct)` | `GyroCalibration` на 2 с |
| `DemoAsync(client, power%, ct)` | Сценарий из [§4.4](#44-кнопки-пресеты) |

Знаки процентов:
- крен «+» вправо;
- тангаж «+» вперёд;
- рыскание «+» поворот вправо.

`FlipDirection`: `Forward`, `Back`, `Left`, `Right`. В UI используется только `Forward`.

При отмене все методы бросают `OperationCanceledException` (`TaskCanceledException`).

### 7.6. Транспорт

```csharp
public interface IDroneTransport : IAsyncDisposable
{
    event Action<byte[]>? DataReceived;
    string Description { get; }
    ValueTask SendAsync(byte[] data, CancellationToken cancellationToken);
}
```

- **`UdpDroneTransport(host, port)`**: `UdpClient`, к которому применён `Connect`, и фоновый цикл приёма.
  Ошибка `ConnectionReset`, то есть ICMP «port unreachable» (Windows сообщает её на следующем `Receive`),
  игнорируется, и приём продолжается.
- **`DryRunTransport`**: ничего не отправляет и ничего не принимает.

### 8.2. `MainViewModel`

Свойства, к которым привязан интерфейс:

| Группа | Свойства |
|---|---|
| Подключение | `Host`, `Port`, `IsDryRun`, `IsConnected`, `IsControlEnabled`, `CanEditConnection`, `ConnectButtonText`, `StatusText` |
| Газ | `Throttle` (double 0…255), `ThrottlePercent`, `IsAltitudeHold` |
| Пресеты | `Power` (10…100), `DurationSeconds` (0,2…5), `ActivePreset`, `IsPresetRunning` |
| Флаги | `IsHeadless`, `IsReturnOrUnlock`, `IsLight` |
| Индикаторы | `RollValue`, `PitchValue`, `ThrottleValue`, `YawValue`, `FlagsText`, `LastPacketHex`, `LogLines` |

Команды:
- подключение: `ToggleConnectionCommand`;
- газ: `ThrottleZeroCommand`, `ThrottleHoldCommand`;
- пресеты: `TakeOffCommand`, `LandCommand`, `HoverCommand`, `ForwardCommand`, `BackCommand`, `LeftCommand`, `RightCommand`,

- остановка: `StopCommand`, `EmergencyStopCommand`;
- журнал: `ClearLogCommand`.

Ключевая логика:

- **`RunPresetAsync(name, preset)`**:
  1. отменяет предыдущий пресет;
  2. создаёт новый `CancellationTokenSource`;
  3. пишет в журнал старт и результат.

  Сбрасывать `ActivePreset` может только «свой» CTS, поэтому отменённый пресет не затирает
  индикатор нового.
- **`OnIsControlEnabledChanged`** включает или выключает цикл в `DroneClient`.
- **`OnThrottleChanged`** сразу передаёт газ в клиент.
- **`OnUiTimerTick`** (100 мс) разбирает последний пакет для индикаторов и пишет его в журнал, если он изменился.

### 8.3. Закрытие окна

`MainWindow.OnClosing` отменяет первое закрытие и асинхронно вызывает `MainViewModel.DisposeAsync()`.
Тот отменяет пресет, отключает управление (уходит `08 01`) и закрывает сокет. Только после этого окно закрывается.

> Закрытие окна **не сажает дрон**. Посадите его до выхода.

## 10. Безопасность

1. **Первые запуски проводите без пропеллеров.** Проверьте, что «Вперёд» действительно наклоняет дрон вперёд,
   а «Поворот вправо» поворачивает вправо. Если направления перепутаны, см. [§12](#12-расширение-проекта).
2. Калибровку гироскопа делайте только на ровной поверхности при выключенных моторах.
3. **STOP не сажает дрон**, он только прекращает команды и переводит дрон в зависание.
   Для посадки нажмите «Посадка».
4. **«Стоп моторов» роняет дрон.** Используйте только в аварийной ситуации.
5. При потере связи (вы вышли из зоны Wi-Fi, закрыли программу или упало приложение) дальнейшее
   поведение зависит от прошивки дрона. Не полагайтесь на автоматическую посадку.
6. Не включайте экспериментальные флаги в полёте.

## 11. Диагностика проблем

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Не собирается, ошибка `NETSDK1045` или «не найден SDK» | Нет .NET 10 SDK | Установить SDK, проверить через `dotnet --list-sdks` |
| Ошибка XAML про неизвестный стиль или ресурс | Другая версия MaterialDesignThemes | Оставить версию 5.2.1 или поправить имя стиля |
| «Ошибка подключения: …» | Неверный IP или ПК не в сети дрона | Проверить Wi-Fi и `ping 192.168.1.1` |
| «Ошибка отправки: …» в журнале | Сеть пропала или выбран другой адаптер | Переподключиться к Wi-Fi дрона |
| Пакеты уходят, а дрон не реагирует | 1) К дрону подключён телефон. 2) Другой тип дрона (JieLi). 3) Брандмауэр | 1) Отключить телефон. 2) См. §13. 3) Разрешить приложению частные сети |
| В журнале нет строк `←` | Дрон не отвечает на этот сокет | Само по себе не ошибка. Проверить в Wireshark (`udp.port == 7099`) |
| Направления перепутаны | Протокол не проверен вживую | См. §12 |
| Кнопки команд серые | Не включена «Передача управления» | Включить переключатель |

**Проверка через Wireshark:** фильтр `udp.dstport == 7099`. Должны идти пакеты `01 01` раз в секунду и,
при включённом управлении, `03 66 … 99` 20 раз в секунду.

## 12. Расширение проекта

**Поменять направление оси.** Поменяйте знак в `MainViewModel` (методы `Forward`, `Left`, `YawLeft` и т.д.)
или в `FlightPresets.MoveAsync`.

**Поменять крен и тангаж местами.** В `DroneProtocol.BuildControlPacket` поменяйте местами `roll` и `pitch`
и обновите тест `Checksum_IsXorOfChannelsAndFlags`, если он завязан на порядок.

**Добавить пресет:**

```csharp
// FlightPresets.cs
public static async Task SquareAsync(DroneClient c, double power, CancellationToken ct)
{
    var side = TimeSpan.FromSeconds(1);
    await MoveAsync(c, 0, power, 0, side, ct);
    await MoveAsync(c, power, 0, 0, side, ct);
    await MoveAsync(c, 0, -power, 0, side, ct);
    await MoveAsync(c, -power, 0, 0, side, ct);
}

// MainViewModel.cs
[RelayCommand]
private void Square()
{
    double power = Power;
    _ = RunPresetAsync("Квадрат", (c, ct) => FlightPresets.SquareAsync(c, power, ct));
}
```

В `MainWindow.xaml` добавьте кнопку с `Command="{Binding SquareCommand}"` и увеличьте `Rows` у `UniformGrid`.

**Новый транспорт** (например, через ретранслятор или для записи в файл): реализуйте `IDroneTransport`
и создайте его в `MainViewModel.ToggleConnectionAsync`.

**Клавиатура или геймпад.** Добавьте `KeyBinding` в `MainWindow.xaml` или обработку XInput.
Методы `SetSticks` и `SetThrottle` потокобезопасны, их можно вызывать хоть 1000 раз в секунду:
отправка всё равно идёт раз в 50 мс.

## Приложение А. Как восстанавливался протокол

Источник: декомпилированный APK (`dex2jar` + JD-GUI), папка `Decompile/src/com`.

| Файл | Что из него взято |
|---|---|
| `cooingdv/kyfpv/fragment/DeviceTXFragment.java` | `UdpComm.getInstance("192.168.1.1", 7099)`; `HeartBeatTask` с `{1, 1}` раз в 1000 мс; `sendFlyControllerData` с префиксом `3`; `{8, 1}` при выключении управления; `new FlyController(handler, 3)`; газ 0 или 128 в зависимости от `isFixedHeightMode` |
| `cooingdv/kyfpv/tools/FlyController.java` | `COMMAND_LENGTH = 8`, `BYTE0 = 102 (0x66)`, `BYTE7 = 153 (0x99)`, `DEFAULT = 128`; период `50 мс`; байт-код `FlyControlTask.run`: сборка флагов `+1 +2 +4 +8 +16 +32 +64 +128`, ограничение каналов, XOR-сумма; длительности сброса флагов (1000, 600, 2000 мс) |
| `cooingdv/kyfpv/socket/UdpComm.java` | Клиентский `DatagramSocket` без `bind`, очередь отправки, приём на тот же сокет |

Расшифровка `FlyControlTask` (по байт-коду):

```
flags = fastFly·1 + fastDrop·2 + emergency·4 + circleTurnEnd·8
      + access$500·16 + (access$600 || unlock)·32 + access$800·64 + gyro·128

turn  = clamp(turn, 1, 255)
accel = (accel == 1) ? 0 : accel
b1    = clamp(b1, 1, 255)
b2    = clamp(b2, 1, 255)
cs    = b1 ^ b2 ^ accel ^ turn ^ (flags & 0xFF)

packet = [0x66, b1, b2, accel, turn, flags, cs, 0x99]
type 3 → delegate.sendFlyControllerData(packet) → [0x03, …packet] → UDP 7099
```

Порядок в пакете: `b1, b2, accel, turn`. В нашей интерпретации это `roll, pitch, throttle, yaw`.

## Приложение Б. Видеопоток и ограничение на одного клиента

Итоги исследования, которое предшествовало проекту:

- Для TX-дронов видео играет IjkPlayer по адресу `rtsp://192.168.1.1:7070/webcam`
  (строка подставлена прямо в `DeviceTXFragment.java`, константа `Config.PREVIEW_ADDRESS` нигде не используется).
- Приложение **не блокирует порт**: на стороне дрона оно только клиент. Ограничение «один зритель» задаёт
  RTSP-сервер в прошивке дрона.
- Приложение переподключается к видео через 500 мс после любой ошибки (`stopAndRestartPlayback`), поэтому
  сразу забирает освободившийся слот.
- JieLi-дроны вообще не отдают RTSP. Поток идёт по собственному протоколу (TCP 2229 или UDP 2224), а нативная
  библиотека переупаковывает его в RTP на `127.0.0.1:6666` **самого телефона** (`SDPServer`, порт 6789).

Чтобы смотреть видео одновременно с управлением, к дрону должен подключаться один клиент-ретранслятор,
который раздаёт поток остальным. Пример конфигурации [mediamtx](https://github.com/bluenviron/mediamtx):

```yaml
paths:
  drone:
    source: rtsp://192.168.1.1:7070/webcam
    rtspTransport: tcp
    sourceOnDemand: no
```

Зрители открывают `rtsp://<ip_ретранслятора>:8554/drone`. Управление из этого проекта
идёт напрямую на `192.168.1.1:7099` и ретранслятору не мешает.
